**Правильный ответ:** `25`

**Объяснение:** Значение 25 не будет выведено, так как age изменяется на 30 внутри функции, а затем выводится локальная переменная user с age: 40.

### 8. Метод filter()

**Вопрос:** Какое из следующих утверждений о методе массива `filter()` верно?

-   `filter()` возвращает логическое значение `true` или `false` в зависимости от того, прошли ли все элементы массива заданную проверку
-   `filter()` по умолчанию удаляет элементы массива, индексы которых кратны 2, даже если в переданном коллбэке этого не указано
-   `filter()` перед выполнением фильтрации сначала автоматически сортирует массив в порядке возрастания, чтобы упростить поиск элементов
-   `filter()` изменяет исходный массив, удаляя все элементы, которые не прошли проверку
-   `filter()` создаёт и возвращает новый массив, содержащий только те элементы, для которых коллбэк-функция вернула `true`

**Правильный ответ:** `filter() создаёт и возвращает новый массив, содержащий только те элементы, для которых коллбэк-функция вернула true`

**Объяснение:** filter() не изменяет исходный массив, а создает новый с отфильтрованными элементами.

### 12. Event Loop и очереди задач

**Вопрос:** Какой результат выполнения этого кода будет неизменно верным?

```javascript
console.log(1);
setTimeout(() => {
    console.log(2);
    Promise.resolve().then(() => {
        console.log(3);
    });
}, 0);
Promise.resolve().then(() => {
    console.log(4);
});
requestAnimationFrame(() => {
    console.log(5);
    setTimeout(() => {
        console.log(6);
    }, 0);
});
console.log(7);
```

-   Порядок 5, 6 может поменяться местами, если requestAnimationFrame вызовется позже setTimeout
-   requestAnimationFrame блокирует очередь микрозадач, поэтому 4 может задержаться
-   1, 7, и 4 всегда будут выведены раньше, чем 2, 3, 5, и 6, вне зависимости от нагрузки
-   5 будет выведено раньше 4, так как requestAnimationFrame срабатывает до микрозадач
-   3 может появиться раньше 2, если Promise.resolve() будет оптимизирован движком

**Правильный ответ:** `1, 7, и 4 всегда будут выведены раньше, чем 2, 3, 5, и 6, вне зависимости от нагрузки`

**Объяснение:** Синхронный код и микрозадачи (Promise) всегда выполняются раньше макрозадач (setTimeout) и requestAnimationFrame.

### 26. Оптимизация SPA приложений

**Вопрос:** Ваше SPA (Single Page Application) содержит огромный объём JavaScript-кода, который передается клиенту целиком, что замедляет начальный рендер. -   Отложенная загрузка компонентов, чтобы загружать неиспользуемые компоненты только при необходимости и уменьшить размер загружаемого кода
-   Динамическое разделение кода с использованием динамического импорта, чтобы загружать модули по мере необходимости и уменьшить размер бандла

-   Использование Web Workers для вычислений, чтобы переместить тяжёлые операции в фоновый поток и не блокировать основной поток рендеринга
-   Server-Side Rendering (SSR), чтобы предварительно рендерить контент на сервере и передавать уже готовый HTML, ускоряя загрузку страниц

**Правильный ответ:** `Динамическое разделение кода с использованием динамического импорта, чтобы загружать модули по мере необходимости и уменьшить размер бандла`

**Объяснение:** Code splitting является основным методом для уменьшения размера начального бандла SPA.

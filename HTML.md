### 1. Web Components и слоты

**Вопрос:** Какой HTML-тег используется в Web Components для создания местозаполнителя в пользовательском компоненте?

-   `<yield>`
-   `<template>`
-   `<slot>`
-   `<insert>`
-   `<placeholder>`

**Правильный ответ:** `<slot>`

**Объяснение:** Тег `<slot>` используется в Web Components для создания местозаполнителей, куда может быть вставлен контент из внешнего документа. Это основной механизм для создания переиспользуемых компонентов с настраиваемым содержимым.

### 2. Шаблоны и отложенный рендеринг

**Вопрос:** Вы хотите заранее задать блок HTML, который не будет отображаться на странице, но может быть вставлен в DOM через JavaScript. Какой тег вы используете?

-   `<fragment>`
-   `<template>`
-   `<slot>`
-   `<div hidden>`
-   `<noscript>`

**Правильный ответ:** `<template>`

**Объяснение:** Тег `<template>` предназначен для хранения HTML-разметки, которая не отображается при загрузке страницы, но может быть динамически добавлена в DOM с помощью JavaScript. Это идеальное решение для создания шаблонов и компонентов.

### 3. Поведение элемента template

**Вопрос:** Рассмотрите фрагмент кода:

```html
<template>
    <h2>Заголовок</h2>
    <p>Текст</p>
</template>
```

Какой эффект от использования этого кода при загрузке страницы?

-   Контент будет загружен, но не отрисован до вызова скрипта
-   Элементы `<h2>` и `<p>` будут доступны скриндерам
-   Контент загрузится, но не будет доступен в DOM
-   Контент отобразится как обычно
-   Контент загрузится в скрытом iframe

**Правильный ответ:** `Контент будет загружен, но не отрисован до вызова скрипта`

**Объяснение:** Содержимое элемента `<template>` загружается и парсится браузером, но не отображается на странице и не доступно через обычные методы DOM до тех пор, пока не будет активировано через JavaScript с помощью cloneNode() или аналогичных методов.

### 4. Элементы для отображения значений

**Вопрос:** Вы хотите визуально отразить, что значение оценки находится в пределах нормального диапазона, но может стать тревожным при выходе за границу. Какой элемент подойдёт лучше всего?

-   `<range>`
-   `<meter>`
-   `<progress>`
-   `<output>`
-   `<datalist>`

**Правильный ответ:** `<meter>`

**Объяснение:** Элемент `<meter>` предназначен для отображения скалярного значения в известном диапазоне или дробного значения. Он идеально подходит для показа уровней, оценок, использования диска, температуры и других измерений, где важно показать текущее значение относительно нормального диапазона.

### 5. Доступность форм и связь элементов

**Вопрос:** Рассмотрите следующий код:

```html
<fieldset>
    <legend>Адрес</legend>
    <label for="city">Город:</label>
    <input id="city" type="text" />
    <label for="zip">Индекс:</label>
    <input type="text" />
</fieldset>
```

Что нужно исправить для улучшения доступности и правильной связи?

-   Добавить `for="city"` к первой метке
-   Добавить атрибут `id="zip"` ко второму `<input>`
-   Переместить `<legend>` внутрь `<label>`
-   Удалить `legend`, он не нужен
-   Подсоединить оба `label` одному `input`

**Правильный ответ:** `Добавить атрибут id="zip" ко второму <input>`

**Объяснение:** Второй label имеет атрибут `for="zip"`, но соответствующий input не имеет `id="zip"`. Для правильной связи метки с полем ввода значения атрибутов `for` у label и `id` у input должны совпадать. Это критично для доступности и работы скринридеров.

### 6. Валидация форм HTML5

**Вопрос:** Рассмотрите следующий фрагмент кода:

```html
<form>
    <input type="email" name="user_email" required />
    <input type="submit" />
</form>
```

Какая ошибка валидации возможна при отправке этой формы?

-   Поле обязательно для заполнения, и при пустом значении форма не отправится
-   Поле не имеет id
-   Поле должно иметь placeholder
-   Значение email не будет сохранено
-   Поле нужно обернуть в `<label>`

**Правильный ответ:** `Поле обязательно для заполнения, и при пустом значении форма не отправится`

**Объяснение:** Атрибут `required` делает поле обязательным для заполнения. Браузер автоматически проверит, что поле не пустое и содержит валидный email адрес перед отправкой формы. Если поле пустое, браузер покажет сообщение об ошибке и предотвратит отправку формы.

### 7. Управление табуляцией и доступность

**Вопрос:** Какой атрибут следует добавить к интерактивному элементу, чтобы исключить его из порядка табуляции, но при этом оставить доступным для чтения скринридером?

-   `aria-hidden="true"`
-   `tabindex="-1"`
-   `role="presentation"`
-   `tabindex="0"`
-   `focusable="false"`

**Правильный ответ:** `tabindex="-1"`

**Объяснение:** Атрибут `tabindex="-1"` исключает элемент из естественного порядка табуляции, но при этом элемент остается программно фокусируемым и доступным для скринридеров. Это полезно для элементов, которые должны получать фокус программно, но не должны быть частью последовательной навигации клавиатурой.

### 8. ARIA роли и доступность кнопок

**Вопрос:** Рассмотрите следующий код:

```html
<div role="button">Нажми меня</div>
```

Какая проблема нарушает доступность элемента?

-   Кнопка недоступна с клавиатуры из-за отсутствия `tabindex`
-   Следует заменить `<div>` на `<p>`
-   Элемент не может быть нажат
-   Элемент не будет озвучен скринридером
-   Отсутствует атрибут `aria-role`

**Правильный ответ:** `Кнопка недоступна с клавиатуры из-за отсутствия tabindex`

**Объяснение:** Хотя `role="button"` сообщает скринридерам, что элемент является кнопкой, `<div>` по умолчанию не может получать фокус клавиатуры. Для обеспечения полной доступности необходимо добавить `tabindex="0"`, чтобы элемент мог получать фокус при навигации клавиатурой, а также обработчики событий для клавиш Enter и Space.

### 9. Кастомные кнопки и моторные нарушения

**Вопрос:** Вы проектируете кастомную кнопку без использования `<button>` и создаёте такой фрагмент:

```html
<div role="button" tabindex="0" onclick="doAction()">Сохранить</div>
```

Как это влияет на доступность для пользователей с нарушениями моторики?

-   Мышь будет блокировать работу скринридера
-   Роль `button` работает только на `<button>`
-   Кнопка недоступна для фокусировки
-   Всё реализовано корректно и не требует доработки
-   Элемент не обрабатывает клавишу Enter/Space

**Правильный ответ:** `Элемент не обрабатывает клавишу Enter/Space`

**Объяснение:** Кастомная кнопка с `onclick` обрабатывает только клики мыши. Для пользователей с моторными нарушениями, которые используют клавиатуру, необходимо добавить обработчики событий `onkeydown` или `onkeyup` для клавиш Enter и Space, чтобы кнопка была полностью доступной при навигации с клавиатуры.

### 10. Оптимизация структуры DOM

**Вопрос:** Какой из вариантов лучше минимизирует глубину DOM и при этом сохраняет читаемую структуру для простого текста с заголовком и описанием?

-   `<header><h2>Заголовок</h2></header><main><p>Описание</p></main>`
-   `<div><div><h2>Заголовок</h2><div><p>Описание</p></div></div></div>`
-   `<section><h2>Заголовок</h2><p>Описание</p></section>`
-   `<div><span><h2>Заголовок</h2><span><p>Описание</p></span></div>`
-   `<article><div><h2>Заголовок</h2></div><div><p>Описание</p></div></article>`

**Правильный ответ:** `<section><h2>Заголовок</h2><p>Описание</p></section>`

**Объяснение:** Этот вариант имеет минимальную глубину DOM (всего 2 уровня вложенности), использует семантически правильный элемент `<section>` для группировки связанного контента, и не содержит лишних оберток. Структура остается понятной как для разработчиков, так и для технологий доступности.

### 11. Избыточная вложенность элементов

**Вопрос:** Рассмотрите следующий фрагмент HTML:

```html
<div>
    <div>
        <div>
            <span>
                <b>Заголовок</b>
            </span>
        </div>
    </div>
</div>
```

Какую проблему с точки зрения DOM и рендеринга он содержит?

-   Некорректное использование и внутри `span`
-   Избыточная вложенность div-ов увеличивает глубину DOM
-   Этот код вызовет ошибку браузера
-   Следует заменить `span` на `h1`
-   Отсутствует семантическая структура

**Правильный ответ:** `Избыточная вложенность div-ов увеличивает глубину DOM`

**Объяснение:** Данный код содержит избыточные уровни вложенности элементов `<div>`, которые не несут смысловой нагрузки. Глубокая вложенность DOM-элементов замедляет рендеринг страницы, увеличивает потребление памяти и усложняет CSS-селекторы. Такую структуру можно упростить до простого `<b>Заголовок</b>` или семантически правильного `<h1>Заголовок</h1>`.

### 12. Оптимизация рендеринга списков

**Вопрос:** Как изменение структуры с 10 одинаковых вложенных блоков `<div>` на один блок со списком `<ul><li>` повлияет на рендеринг?

-   Не повлияет, т.к. все элементы одинаковы по визуальному весу
-   Повысит семантическую ясность и упростит стилизацию без влияния на производительность
-   Увеличит количество DOM-узлов и замедлит рендеринг
-   Ухудшит доступность для скринридеров
-   Сократит глубину и улучшит производительность за счёт оптимизации браузерного рендера

**Правильный ответ:** `Сократит глубину и улучшит производительность за счёт оптимизации браузерного рендера`

**Объяснение:** Замена множественных вложенных `<div>` на структуру `<ul><li>` сокращает глубину DOM-дерева и использует семантически корректные элементы. Браузеры оптимизированы для работы с списками, что улучшает производительность рендеринга. Кроме того, такая структура лучше для доступности и проще в стилизации.

### 13. Валидные имена для Custom Elements

**Вопрос:** Какое из следующих имён допустимо для custom element по спецификации HTML?

-   `<widget>`
-   `<_my-element>`
-   `<user-profile>`
-   `<custom.element>`
-   `<mybutton>`

**Правильный ответ:** `<user-profile>`

**Объяснение:** По спецификации HTML имена пользовательских элементов (custom elements) должны содержать дефис (-) для предотвращения конфликтов с будущими стандартными HTML элементами. Имя должно начинаться с ASCII буквы и содержать только ASCII буквы, цифры и дефисы. `<user-profile>` соответствует всем этим требованиям, в то время как другие варианты нарушают правила именования.

### 14. JSX и передача CSS-классов

**Вопрос:** Какой из следующих JSX-фрагментов будет валиден и обеспечит корректную передачу CSS-класса?

-   `<div classname="container">контент</div>`
-   `<div styleclass="container">контент</div>`
-   `<div class="container">контент</div>`
-   `<div :class="container">контент</div>`
-   `<div class-name="container">контент</div>`

**Правильный ответ:** `<div class="container">контент</div>`

**Объяснение:** В JSX для передачи CSS-класса используется стандартный HTML атрибут `class`. Хотя в React долгое время использовался `className` из-за конфликта с зарезервированным словом JavaScript, современные версии React поддерживают стандартный атрибут `class`. Остальные варианты являются неверными синтаксисами для передачи CSS-классов.

### 15. Web Components и использование слотов

**Вопрос:** Рассмотрите шаблон Web Component:

```html
<template>
    <div class="wrapper">
        <slot name="title"></slot>
        <slot name="content"></slot>
    </div>
</template>
```

Какая ошибка допущена в следующем использовании?

```html
<custom-box>
    <h2>Заголовок</h2>
    <p>Текст</p>
</custom-box>
```

-   Отсутствуют теги `slot` в шаблоне
-   Нельзя использовать обычные теги внутри компонента
-   Не указаны атрибуты `slot` у вложенных элементов
-   Используются теги вне шаблона
-   Нужно добавить `exportparts` в корень

**Правильный ответ:** `Не указаны атрибуты slot у вложенных элементов`

**Объяснение:** В шаблоне определены именованные слоты `name="title"` и `name="content"`, но при использовании компонента элементы `<h2>` и `<p>` не имеют соответствующих атрибутов `slot="title"` и `slot="content"`. Без этих атрибутов содержимое попадет в безымянный слот по умолчанию, если он существует, или не будет отображено вовсе.
